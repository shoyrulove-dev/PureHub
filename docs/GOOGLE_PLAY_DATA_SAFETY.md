# Google Play Data safety worksheet

This worksheet applies to the Standard Android bundle for PureHub beta.54. It is an implementation checklist, not a substitute for reviewing the final Play Console form and the exact uploaded AAB.

## Product declarations

- No mandatory account.
- No advertising SDK or ads in the Android app.
- No analytics SDK in the Android app.
- No sale of user data.
- Local app data can be deleted by clearing app storage or uninstalling PureHub.
- The public privacy policy is `https://hub.blissbiovn.com/en/privacy` and is linked from Android Settings.

## Data handled locally

The following can be processed or stored on the device when the user chooses the related tool: camera frames and imported images, OCR text, QR history, documents and PDFs, microphone levels or optional screen-recording audio, screen recordings, Wi-Fi observations, survey plans and measurements, habits, expenses, vault entries, preferences, and exported files.

Local processing alone is not off-device collection. Re-check every future SDK and network endpoint before keeping a “not collected” answer.

## User-started network activity

- Wi-Fi diagnostics can contact a selected speed-test endpoint, public DNS resolver, router console, or optional local controller only after the user starts the action.
- Community, source-code, privacy-policy, update, and tester links open an external browser or service selected by the user.
- Normal network operation exposes request metadata such as IP address to the destination. PureHub does not add an advertising identifier or account identifier.

Confirm in Play Console whether any endpoint retains request logs or results. If PureHub begins retaining diagnostics, support messages, identifiers, or usage events from the Android app, update both this worksheet and the Data safety form before release.

## Permissions and purpose

- Camera: QR, OCR, document scanning, and color capture.
- Microphone: sound meter and optional screen-recording narration.
- Nearby Wi-Fi and foreground location: nearby network scanning where Android requires it.
- Notifications: visible Pomodoro, Wi-Fi monitoring, and screen-recording controls.
- Media projection foreground service: user-approved screen recording.
- Internet and network state: user-started connected diagnostics, update/community links, and Standard OCR dependencies.
- Wallpaper: user-selected wallpaper actions.

## Console checklist

1. Upload the signed AAB and review the permission list generated by Play Console.
2. Complete Data safety from the uploaded Standard bundle, not the retired F-Droid flavor.
3. Declare no ads for Android.
4. Complete target audience, content rating, app access, and foreground-service declarations.
5. Add reviewer instructions for Wi-Fi scanning, screen recording, OCR, and permission-denial fallbacks.
6. Reconcile every answer with the privacy policy before submitting the closed test.
